# 사람 확인형 예약 도우미 — 설계

작성일: 2026-10-17

## 의도와 이유

예약 과정의 반복적인 수고(대기열 지켜보기, 같은 정보 반복 입력, 진행 상황 확인)를 도우미가 맡고,
사람은 꼭 필요한 순간에만 최소한의 동작(Enter 한 번, 숫자 키 하나, CAPTCHA 입력)으로 개입한다.
특정 사이트 전용이 아니라, 사이트마다 한 번 손으로 진행하는 과정을 녹화해 두면 이후 재생하는 범용 도구다.

이 도구의 가치는 **수고 절감과 개입 편의**이며, 사람보다 빨리 한정 자원을 선점하는 것이 아니다.

## 목표

1. 사이트별 예약 흐름을 사람이 한 번 진행하며 **녹화**하고 파일로 저장한다.
2. 녹화를 **재생**하되, 날짜·시간·이름·연락처 등 값은 실행 시 지정한 값으로 치환한다.
   (녹화의 "날짜 클릭" 단계는 "지정 날짜 칸을 찾아 클릭"으로 일반화된다.)
3. 사용자가 미리 로그인해 둔 Chrome에 연결해 로그인 상태를 그대로 사용한다.
4. 사람 개입 지점에서 편하게 부르고, 편하게 처리하게 한다(아래 "개입 UX").

## 비목표

- CAPTCHA·봇 검증의 자동 해독 또는 우회.
- 대기열·접근 제한·속도 제한의 우회(새로고침 폭주, 다중 세션/다중 계정, 요청 위조 등).
- 사람 확인 없이 최종 제출하는 모드, 일정 시간 후 자동 승인.
- 마감 시 대안을 도우미가 스스로 선택하는 것.
- 좌석맵 자동 좌석 선택 같은 사이트 특화 최적화.
- 로그인 자동화(로그인은 사람이 사전에 한다).

## 실패로 간주하는 것(기술적으로 돌아가더라도)

- 사람이 모르는 사이에 제출이 이루어지는 경우.
- 사람을 불렀는데 알아채지 못할 정도로 알림이 약한 경우.
- 사람이 브라우저에서 직접 처리했는데 도우미가 그걸 인식 못 하고 멈춰 있거나 엉뚱한 동작을 이어가는 경우.
- 녹화 당시와 화면이 조금 달라졌다는 이유만으로 매번 사람을 부르는 경우(합리적 수준의 견고성 필요).

## 제약

- 환경: Windows와 macOS 모두 지원. 사용자가 명령줄에서 Python으로 직접 실행한다(패키징된 exe/앱 불필요).
- 경로, Chrome 실행 위치, 알림(Windows 토스트 / macOS 알림센터), 소리, 창 전면화는 OS별로 구현한다.
- 대상 사이트의 자동화 허용 여부는 사용자가 판단한다. README에 "사용 전 대상 사이트의 이용약관에서 자동화 허용 여부를 확인할 것"을 명시한다.
- 요청 빈도는 사람이 손으로 진행하는 수준을 넘지 않는다(대기 중 폴링은 DOM 관찰 위주, 페이지 새로고침 반복 금지).

## 결정된 사항

### 기술 스택 (Claude의 판단)
- Python + Playwright.
- 사용자가 디버깅 포트를 열어 실행한 Chrome에 `connect_over_cdp`로 연결. 실행 방법(바로가기/스크립트)을 도구가 안내·제공한다.
- 낯선 화면 해석에는 Claude API(스크린샷 + 단순화한 DOM)를 사용해 "다음에 할 행동" 제안을 만든다. API 키가 없으면 이 기능 없이 바로 사람을 부른다. (Claude의 판단)

### 녹화
- 사람이 예약 과정을 끝까지 진행하는 동안 클릭·입력·선택·페이지 이동을 순서대로 기록한다.
- 각 단계에 대해 견고한 대상 식별 정보(역할/라벨/텍스트, CSS 선택자 후보 여러 개, 화면상 위치)를 함께 저장한다.
- 입력값 중 실행 시 바뀔 값(날짜, 시간, 이름, 연락처 등)은 녹화 직후 사람이 변수로 지정한다.
- 녹화 결과는 사람이 읽고 고칠 수 있는 파일(YAML 또는 JSON)로 저장한다.
- 마지막 제출 단계는 녹화 시 "최종 제출"로 표시하며, 재생 시 항상 확인 단계가 된다.

### 재생과 상태 처리
| 상황 | 도우미 동작 |
|---|---|
| 녹화대로 진행 가능 | 그대로 진행 |
| 대기열 화면 | 우회 없이 대기, 입장되면 알아서 이어서 진행(사람 신호 불필요) |
| CAPTCHA·봇 검증 | 사람 호출, 입력칸에 포커스, 화면 전환 감지 시 자동 재개 |
| 낯선 화면 | 화면 해석 후 제안을 확인 창에 표시 → Enter 승인 또는 사람이 브라우저에서 직접 처리(변화 감지 후 재개) |
| 지정 날짜·시간 마감 | 대안을 번호 목록으로 제안, 숫자 키로 사람이 선택 |
| 최종 제출 | 요약(날짜·시간·예약자 정보·결제 방식) 표시, Enter 한 번으로 제출 |

### 시작 방식 (Claude의 판단)
- 즉시 시작 또는 지정 시각 시작. 지정 시각 시작은 그 시각에 페이지를 한 번 열고 흐름을 시작하는 것이며, 시각 전후로 새로고침을 반복하지 않는다.

### 개입 UX
- 호출: 소리 + OS 알림 + 브라우저 창 전면화 + 텔레그램 메시지를 동시에. 텔레그램은 봇 토큰과 chat id를 설정 파일에 넣으면 활성화된다(사용자 결정).
- 텔레그램 메시지에는 상황 설명과 현재 화면 스크린샷을 첨부한다. 승인·선택은 PC에서 한다(원격 승인은 범위 밖, Claude의 판단).
- 화면 해석용 스크린샷/DOM은 마스킹 없이 Claude API로 보낸다(사용자 결정).
- 확인 창: 항상 위에 뜨는 작은 창. 현재 상황, 제안 내용, 가능한 키(Enter=승인, 숫자=선택, Esc=중단)를 표시.
- 자동 승인 타임아웃 없음.
- 모든 단계와 개입 내역을 실행 로그로 남긴다(스크린샷 포함).

### 결제 경계 (Claude의 판단 — 사용자의 최초 요구 "결제 전 단계까지 수행, 결제는 사람" 기준)
- "최종 제출"은 예약을 확정하는 버튼(무통장 입금 선택 후 예약 완료, 또는 결제창으로 넘어가는 버튼)이다.
- 결제 수단 선택(예: 무통장 입금 라디오)은 녹화 단계로 재생 가능하다.
- 카드·간편결제·본인인증 등 결제사 팝업/iframe 안의 동작은 녹화·재생하지 않는다. 결제창이 뜨면 사람에게 넘기고 실행을 종료한다.
- 카드번호 등 결제 정보는 녹화 파일·로그에 절대 저장하지 않는다.

### 마지막 단계 녹화 (Claude의 판단)
- 녹화 중 사람이 단축키로 "다음 클릭은 최종 제출"을 지정하면, 녹화기는 그 클릭을 실제로 전달하지 않고 대상 정보만 기록한 뒤 녹화를 끝낸다. 녹화 때문에 실제 예약이 생기지 않는다.

### Chrome 프로필 (Claude의 판단)
- 최신 Chrome은 기본 프로필에서 원격 디버깅을 막으므로, 도우미 전용 프로필(별도 user-data-dir)을 사용한다. 사람은 이 프로필에서 한 번 로그인해 두면 이후 유지된다. 전용 프로필로 Chrome을 띄우는 바로가기를 도구가 만들어 준다.

### 마감 시 대안 (Claude의 판단)
- 실행 시 사람이 원하는 후보를 우선순위대로 여러 개 지정할 수 있다. 1순위가 마감이면 현재 화면에서 아직 가능한 후보를 번호로 보여준다.
- 지정 후보가 모두 마감이면 현재 화면에 보이는 가능 항목을 보여준다. 선택은 항상 사람이 한다.
- 다른 날짜처럼 몇 단계 되돌아가야 하는 대안은 녹화된 해당 단계부터 다시 진행한다.

## 빌더에게 맡기는 것
- 대기열/CAPTCHA/낯선 화면 감지 방식(휴리스틱 + 화면 해석 조합)의 세부.
- 확인 창 구현 수단(tkinter 등, Windows/macOS 양쪽에서 동작해야 함).
- 녹화 파일 스키마 세부, 선택자 재탐색 전략.
- 프로젝트 구조, 테스트 전략(로컬 가짜 예약 사이트를 테스트 대상으로 만드는 것을 권장).
